# Stripe foundation — how it fits together

The whole paid loop, and what's built vs. what you wire up.

```
  Customer clicks "Buy" on the website
        |  (Stripe Payment Link — you create these, 10 min)
        v
  Stripe hosts checkout, takes payment (test card 4242 4242 4242 4242)
        |
        v
  Stripe fires checkout.session.completed  --->  issue-license-webhook.js
                                                    |  generates ORCH-... key
                                                    |  (TODO: email it, store it)
                                                    v
  Customer gets a key  --->  pastes it into Orchard Mirror
                                    |  OfflineBetaGateway.Evaluate(key)
                                    v
                              app unlocks
```

## What's already built and proven
- **The app side** (`src/Orchard.Mirror.Shell/Licensing.cs`): parses keys, validates them offline,
  reports the tier. Unit-tested; 6 tests in the suite.
- **The server side** (`issue-license-webhook.js`): generates keys in the identical format.
- **Cross-checked:** keys generated by the Node webhook were validated by the app's key logic — they
  match, so a key the server issues *will* be accepted by the app. (Verified by running both.)

## What you do (in order)
1. **Stripe account + test products** — see `../LAUNCH_PACK.md` Part 3. Create Monthly/Yearly/Lifetime
   products in **test mode**, grab their Price IDs and Payment Links.
2. **Wire the website** — paste the three Payment Links into `../index.html` (replace the
   `REPLACE_WITH_STRIPE_TEST_LINK_*` placeholders).
3. **Deploy the webhook** — drop `issue-license-webhook.js` on Vercel/Netlify/Cloudflare (free tiers
   work). Set `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`. Paste your real Price IDs into
   `PRICE_TO_TIER`. Add the endpoint URL in Stripe → Developers → Webhooks.
4. **Fill the two TODOs** — store issued keys (any DB, even a Google Sheet to start) and email them
   (Resend/Postmark free tiers). Until then the key is only printed to the server log.
5. **Test the whole loop** in test mode before flipping to live.

## Keep in sync
If you ever change the key alphabet or the checksum, change it in **both** `Licensing.cs` and
`issue-license-webhook.js`, or issued keys stop validating. There's a comment saying so in each file.

## Before going live (not test)
- Stripe verifies your identity + bank (only you can do this).
- Real Terms, Privacy, and Refund pages linked from checkout (drafts in `../legal/`).
- Handle refunds/cancellations → deactivate keys (the `charge.refunded` TODO).
